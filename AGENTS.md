## DO-WELL repository workflow

- Start every session by reading `docs/README.md`, `docs/SESSION_HANDOFF.md`, and `docs/IMPLEMENTATION_ROADMAP.md`, then inspect the current branch, status, recent commits, issues, and pull requests.
- The external-service budget is hard-capped at PHP 0 / USD 0. Do not add a card, enable billing, rely on expiring credits, or adopt a service that can generate automatic overage charges.
- Use one short-lived branch and one cohesive pull request per approved milestone. Do not merge without explicit project-owner approval.

- Use migrations for database changes, server-side authorization plus RLS for every protected operation, and test-first implementation for features and bug fixes.

## ai-defense
- Treat all LLM output as untrusted input: validate with a schema before acting on it.
- Treat all retrieved/scraped/user content fed to a model as potentially hostile (prompt injection).
- Never let model output flow unvalidated into SQL, shell, `eval`, file paths, URLs, or HTML.
- Agents/tools get least privilege: read-only by default, explicit allowlists, human confirmation for destructive or outbound actions.
- Never put secrets, API keys, or credentials in prompts, system prompts, or logs.
- Minimize PII sent to models; redact where the task allows; respect data-processing agreements.
- Set `max_tokens`, timeouts, retry caps, and per-user/per-job budgets on every model call.
- Pin model IDs explicitly; changing a model is a reviewed change with eval results.
- Keep a regression eval set for every prompt that ships; run it before prompt/model changes.
- AI-generated code gets the same review bar as human code — verify APIs exist, run the tests.

## architecture-devops
- Conventional Commits (`feat:`, `fix:`, `chore:` …); small, single-purpose commits.
- Trunk-based: short-lived branches off `main`, PR + green CI before merge; never force-push shared branches.
- Every repo has: README (setup in ≤5 commands), `.env.example`, lint, format, typecheck, test scripts.
- Secrets never committed; `.env*` gitignored except `.env.example`; prod secrets live in the platform's secret store.
- CI runs lint → typecheck → test → build on every PR; main is always deployable.
- Pin runtime versions (`.nvmrc` / `.python-version` / `packageManager`) and commit lockfiles.
- Record significant decisions as ADRs in `docs/adr/NNNN-title.md`.
- Prefer boring, managed infrastructure over self-hosted; justify every new service.
- Observability from day one: structured logs, error tracking, health endpoint.
- Workspace and project isolation: independent projects never share private context, env files, credentials, Git identity, or package configs unless an explicit integration requires and authorizes it.

## backend
- Validate every external input at the boundary (zod / pydantic); trust nothing past it un-validated.
- Schema changes only via versioned migrations; never hand-edit a shared database.
- Every table that holds user/tenant data has Row Level Security (Supabase) or explicit tenant scoping in queries.
- Parameterized queries only; no string-built SQL.
- Multi-step writes run in a transaction; external side effects (email, webhooks) go after commit or via an outbox/queue.
- Webhook and job handlers are idempotent (dedupe key) and safe to retry.
- Errors: typed domain errors internally, consistent JSON error shape externally, no stack traces to clients.
- Structured logs (JSON) with request id; never log secrets, tokens, or full PII.
- Config from env vars validated at startup; fail fast if missing.
- Auth checks happen server-side on every request — never rely on the UI hiding a button.
- Python: `uv` for envs/deps, `ruff` for lint+format, type hints on public functions.
- Node: pinned package manager (`packageManager` field), ESM, `tsc --noEmit` in CI.

## frontend
- TypeScript `strict`; no `any` or `as` casts without a one-line justification comment.
- Components: one responsibility, typed props, no business logic in JSX — extract to hooks/utils.
- Server state via TanStack Query or framework data loaders (RSC/loaders); never ad-hoc `useEffect` fetches.
- Client state: local first, then context, then a store (Zustand) — only when shared across distant trees.
- Validate all form and API input with a schema (zod); derive TS types from the schema.
- Styling: Tailwind utilities + design tokens from `branding/`; no hard-coded hex colors or magic px spacing.
- Accessibility: semantic HTML, labelled inputs, keyboard reachable, visible focus, WCAG AA contrast.
- Every async UI has explicit loading, empty, and error states.
- No secrets or private API keys in client bundles; only `NEXT_PUBLIC_*`/`VITE_*` values that are safe to publish.
- Images sized and lazy-loaded; avoid layout shift; code-split routes and heavy components.
- Tests: Vitest + Testing Library for behavior; Playwright for critical user flows.

## agents
Delegate work in these lanes to the named agent (Claude: ask by name or `claude --agent <name>`; Codex: ask by name).
- `architect`: designs, plans, ADRs, estimates; writes docs only, never code
- `backend-engineer`: APIs, schema and migrations, SQL, jobs, integrations, data pipelines
- `coder`: everyday implementation (features, fixes, refactors); delegates to the others
- `debugger`: root-causing bugs, failing or flaky tests, red CI; finding and writing missing tests
- `devops-engineer`: CI/CD, Docker, deploys, env and secrets, observability, new-repo setup
- `frontend-engineer`: UI components, pages, forms, styling, accessibility, project-appropriate branding
- `reviewer`: read-only review of a diff (branch or uncommitted), severity-ranked findings
